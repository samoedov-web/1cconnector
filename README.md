# Коннектор «Блокчейн → 1С»

Сервер, который автоматически собирает транзакции по кошелькам компании из
блокчейнов (read-only, без приватных ключей), обогащает их учётными данными
и выгружает в 1С готовые проекты документов для учёта расчётов по ВЭД в
цифровой валюте.

Полное ТЗ уровня архитектуры: [docs/architecture.md](docs/architecture.md).

## Принципы

1. **Read-only к блокчейну** — никаких приватных ключей и подписи транзакций.
2. **1С — мастер-система учёта** — коннектор поставляет первичку и проекты документов.
3. **Неизменяемость первички** — хэш, сырой ответ ноды, метка времени у каждой транзакции.
4. **On-premise по умолчанию** — Docker Compose на сервере клиента.
5. **Обновляемость форм отчётности** — шаблоны отдельно от ядра.

## Архитектура

```
+----------------------+     +------------------------+     +---------------------+
|  Blockchain Indexer  | --> |  Core Service + DB     | --> |  1C Integration     |
|  (TRON, EVM chains)  |     |  (matching, pricing,   |     |  (расширение 1С +   |
|  ноды / провайдеры   |     |   accounting engine)   |     |   HTTP API обмена)  |
+----------------------+     +------------------------+     +---------------------+
```

| Контур | Код | Что делает |
|---|---|---|
| Индексер | `src/connector/indexer/` | Плагинные `ChainAdapter` (TRON, Ethereum), статусы `seen → confirmed(N) → final`, дедуп по (сеть, хэш, log index), кросс-проверка двух источников |
| Курсы | `src/connector/rates/` | Основной + резервный источник, снимок на момент финальности, цепочка актив → валюта контракта → рубль |
| Матчинг | `src/connector/matching/` | Правила 1–3 (адрес → сумма±допуск → окно графика), частичные оплаты, очередь ручного разбора |
| Учёт | `src/connector/accounting/` | Партии и ФИФО (метод — настройкой), проекты документов «Поступление/Выбытие ЦВ», комиссия сети |
| Конвейер | `src/connector/pipeline.py` | Связка контуров: финальность → матчинг → снимок курса → партия/списание ФИФО → проект документа 1С; идемпотентен, pending-транзакции ждут ручного разбора |
| Обмен с 1С | `src/connector/onec/` | REST для фонового задания 1С, токен, идемпотентность по хэшу транзакции; синхронизация справочников из 1С (GUID контрагентов/договоров/счетов в payload документов) |
| Веб-панель (API) | `src/connector/web/` | Вход по токену, RBAC (admin / operator / auditor), кошельки, очередь разбора (привязка с запоминанием правила), транзакции с фильтрами, справочник контрагентов, дашборд, пользователи, аудит-лог |
| Веб-панель (UI) | `web/` | React + Vite, 7 экранов: мониторинг, очередь разбора, транзакции (карточка + печатные формы), кошельки (+ журнал операций), контрагенты с договорами, пользователи, вход; статика отдаётся FastAPI |
| Печатные формы | `src/connector/reports/` + `templates/reports/` | Акт по крипто-платежу, журнал операций по адресу; HTML/XLSX/JSON; шаблоны обновляются отдельно от ядра; журнал неизменяемости в каждой строке |
| Расширение 1С | `onec-extension/` | Объекты и протокол обмена (отдельная роль разработки) |

## Быстрый старт (разработка)

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest                      # тесты ФИФО, матчинга, финальности, API панели

# Веб-панель (отдельный терминал): дев-сервер проксирует /api на :8000
cd web && npm install && npm run dev
```

## Развёртывание on-premise

```bash
cp .env.example .env        # заполнить токены, ключ панели и источники данных
docker compose up -d        # db + api (:8000, применяет миграции) + indexer
```

Health-check: `GET /health`. OpenAPI: `GET /docs`.

Первый вход в панель: учётка `admin` создаётся при старте из
`CONNECTOR_ADMIN_PASSWORD` (если пользователей ещё нет), токен выдаёт
`POST /api/v1/auth/login`. Схема БД управляется Alembic
(`alembic upgrade head` выполняется в entrypoint контейнера api;
индексер стартует после его health-check — уже на смигрированной схеме).

Печатные формы: `GET /api/v1/reports/payment-act/{tx_id}` и
`GET /api/v1/reports/journal?wallet_id=&date_from=&date_to=`,
параметр `format=html|xlsx|json`. HTML-шаблоны в `templates/reports/`
смонтированы volume-ом — новые формы доставляются заменой файлов,
без пересборки образа.

## Статус относительно дорожной карты MVP (п. 12 ТЗ)

- [x] Каркас трёх контуров, доменная модель, статусы финальности per-network
- [x] Адаптеры TRON (TRC-20) и Ethereum (ERC-20) — базовая индексация
- [x] Движок матчинга (правила 1–3, частичные оплаты) + очередь ручного разбора
- [x] ФИФО по партиям с расшифровкой списаний
- [x] API обмена с 1С (идемпотентность, токен) + протокол для расширения
- [x] Связка «финальность → матчинг → снимок курса → партия/списание ФИФО → документ» (`pipeline.py`, идемпотентная, работает в цикле воркера)
- [x] CI (GitHub Actions): ruff + pytest на Python 3.11/3.12 + проверка миграций
- [x] Управление пользователями: CRUD (admin), смена своего пароля, защита последнего активного администратора, немедленный отзыв доступа отключением
- [x] Курсор синхронизации: повторные опросы идут от последнего блока с запасом на реорг, а не с полного бэкфилла; Ethereum читает историю кусками блоков (лимиты публичных RPC)
- [x] Обработка реоргов в воркере: нефинальные транзакции перепроверяются в канонической цепочке (orphaned / переехавшие в другой блок)
- [x] Кросс-проверка наборов транзакций: опрашиваются все источники, берётся объединение, подтверждённые двумя помечаются cross_checked; курсор не двигается, пока не ответили все источники
- [x] Сид справочников: сети (TRON/Ethereum) и активы (USDT/USDC, боевые адреса контрактов) создаются при первом старте на пустой базе; настройки клиента не перезаписываются
- [x] Догрузка комиссий сети: TRX (gettransactioninfobyid) и газ ETH (receipt) для исходящих; котировки нативных монет — CoinGecko в цепочке фолбэков (биржевой источник клиента подключается первым звеном)
- [x] Алерты мониторинга: журнал в БД + опциональный webhook (недоступность источников, расхождение высот/наборов, реорги); последние алерты — на экране «Мониторинг»
- [x] Неизменяемость первички на уровне БД: PostgreSQL-триггеры запрещают изменение доказательных полей транзакций и любые правки снимков курсов/аудит-лога (см. docs/deployment.md)
- [x] Документация по развёртыванию и безопасности: docs/deployment.md (TLS через reverse proxy, секреты, шифрование в покое, egress, бэкапы, обновления)
- [x] Печатные формы: акт по платежу, журнал операций (обновляемые шаблоны, HTML/XLSX/JSON, журнал неизменяемости)
- [x] Аутентификация веб-панели (токены, RBAC: admin / operator / auditor, bootstrap администратора)
- [x] Миграции Alembic (начальная схема; `create_all` остаётся только как страховка для dev/тестов)
