# Структура расширения «Коннектор Блокчейн» (1С:БП 3.0)

Инструкция для 1С-разработчика: какие объекты создать в Конфигураторе/EDT
и куда положить готовый код. Расширение НЕ изменяет типовую конфигурацию —
только добавляет объекты и реквизиты (режим совместимости — как у типовой).

## Константы

| Имя | Тип | Назначение |
|---|---|---|
| `КоннекторАдрес` | Строка(200) | URL коннектора, например `https://connector.local:8000` |
| `КоннекторТокен` | Строка(200) | Значение `CONNECTOR_ONEC_EXCHANGE_TOKEN` |
| `КоннекторАвтопроведение` | Булево | Ложь — проекты документов (бухгалтер проводит вручную), Истина — авто-проведение |

## Справочники (новые)

- **Криптоактивы** — код, наименование (USDT, USDC), реквизиты: `Сеть`
  (ссылка на БлокчейнСети), `АдресКонтракта` (Строка 128), `Декималы` (Число).
- **БлокчейнСети** — код (`tron`, `ethereum` — совпадает с кодами коннектора),
  наименование, `ПорогФинальности` (Число).
- **КошелькиАдреса** — `Адрес` (Строка 128), `Сеть`, `Владелец`
  (Перечисление: НашаОрганизация / Контрагент), `Контрагент` (ссылка).

## Доработка типовых объектов (добавленные реквизиты)

- Справочник **ДоговорыКонтрагентов**:
  - `РасчетыЦифровойВалютой` (Булево) — признак отбора для выгрузки в коннектор;
  - `УчетныйНомерВЭД` (Строка 50) — учётный номер контракта (валютный контроль).

## Документы (новые)

Общие реквизиты всех трёх: `КлючОбмена` (Строка 256, индексировать!),
`ХэшТранзакции` (Строка 128), `БлокчейнСеть`, `Криптоактив`,
`Количество` (Число 27.18), `МоментОперации` (Дата), `КурсВРубли` (Число 20.6),
`ИсточникКурса` (Строка 100), `СуммаРуб` (Число 15.2).

- **ПоступлениеЦифровойВалюты** — табличная часть `Привязки`:
  `Контрагент`, `Договор`, `НомерИнвойса` (Строка 50), `Сумма` (Число 27.18).
  Движения при проведении: регистр `ПартииЦифровойВалюты` (приход),
  проводки Дт (счёт учёта ЦВ из настроек) / Кт (расчёты с контрагентом).
- **ВыбытиеЦифровойВалюты** — табличные части `Привязки` (как выше) и
  `ПартииСписания`: `ИдентификаторПартии` (Число), `Количество`,
  `СебестоимостьРуб`. Движения: расход партий, финрезультат
  (91.01/91.02 или счета из настроек).
- **КомиссияБлокчейнСети** — без табличных частей; `СуммаРуб` — расход
  (статья затрат из настроек).

## Регистры (новые)

- **ПартииЦифровойВалюты** (регистр накопления, остатки): измерения
  `Криптоактив`, `Кошелек`, `ИдентификаторПартии`; ресурсы `Количество`,
  `СтоимостьРуб`. Заполняется документами; сверяется с ФИФО коннектора.
- **КурсыЦифровыхВалют** (регистр сведений): `Период`, `Криптоактив`,
  `КурсВРубли`, `Источник`.
- **РезультатыСверкиСДепозитарием** (регистр сведений, периодический) —
  режим shadow depository-спеки, ИНФОРМАЦИОННЫЙ (никаких проводок):
  измерения `ИдентификаторЗапуска` (Число), `Статус` (Строка 32);
  реквизиты `ИсточникВыписки` (Строка 64), `ПериодС`/`ПериодПо` (Дата),
  `Правило` (Строка 32), `Пояснение` (Строка 500). Заполняется обменом
  (doc_type = reconciliation_info), перезапись по ИдентификаторЗапуска.

## Регламентное задание

- **СинхронизацияСКоннектором**: метод
  `КоннекторОбмен.СинхронизацияСКоннектором`, расписание — каждые 5 минут.

## Общие модули

- **КоннекторОбмен** (серверный, вызов сервера — Ложь) — готовый код:
  `src/CommonModules/КоннекторОбмен/Module.bsl`. Помечено в коде:
  - запрос счетов (`ДобавитьОткрытыеСчетаДоговора`) подгоняется под
    учётную политику клиента (Счёт покупателю / Счёт от поставщика);
  - `РазложитьСтрокуURI` — взять из БСП (`ОбщегоНазначения.СтруктураURI`)
    или заменить своей функцией разбора URL.

## Роли/права

- Роль **КоннекторОбменПрава**: чтение/запись новых объектов, чтение
  Контрагентов/Договоров/Счетов. Назначается пользователю фонового задания.

## Порядок обмена (соответствует API коннектора)

1. `POST /api/v1/onec/sync` — выгрузка справочников с GUID
   (контрагенты → договоры → счета, в одной пачке).
2. `GET /api/v1/onec/documents?status=draft` — проекты документов;
   в привязках приходят `counterparty_ref`/`contract_ref`/`invoice_ref` —
   GUID объектов 1С, выгруженных на шаге 1.
3. Создание документа по `idempotency_key` (реквизит КлючОбмена) —
   повторная загрузка дублей не создаёт.
4. `POST /api/v1/onec/documents/ack` — `[{idempotency_key, onec_ref}]`,
   где onec_ref — GUID созданного документа.

Заголовок всех запросов: `X-Exchange-Token: <токен>`.
