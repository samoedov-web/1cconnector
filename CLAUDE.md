# Коннектор «Блокчейн → 1С»

Сервер учёта расчётов по ВЭД в цифровой валюте: read-only индексация
TRON/Ethereum, матчинг с контрагентами/контрактами, ФИФО, выгрузка
проектов документов в 1С. Полное ТЗ: `docs/architecture.md`.

## Принципы (не нарушать)

1. **Read-only к блокчейну** — никаких приватных ключей и подписания
   транзакций, ни одного нового места хранения секретов.
2. **1С — мастер-система учёта** — коннектор поставляет первичку и
   проекты документов.
3. **Неизменяемость первички** — сырые ответы внешних источников
   хранятся как получены (+ SHA-256), на PostgreSQL защищены триггерами.
4. **Обновляемые шаблоны отчётности** — формы в `templates/reports/`,
   не зашивать в код.

## Команды

```bash
.venv/bin/python -m pytest -q         # тесты (без сети, SQLite in-memory)
.venv/bin/ruff check src tests scripts
cd web && npm run build               # сборка панели (React + Vite)
CONNECTOR_DATABASE_URL=sqlite:///x.db alembic upgrade head && alembic check
```

Миграции: autogen через Alembic (`migrations/`), для SQLite-совместимости
ALTER-операции — в `op.batch_alter_table`. Все суммы — `Decimal`
(Numeric 38,18), времена — UTC-aware.

## Структура

| Где | Что |
|---|---|
| `src/connector/indexer/` | ChainAdapter (TRON/ETH), финальность, реорги, кросс-проверка |
| `src/connector/pipeline.py` | финальность → матчинг → курс → ФИФО → документ 1С |
| `src/connector/matching/`, `accounting/`, `rates/` | движки ядра (чистая логика, тестируется без БД) |
| `src/connector/onec/` | обмен с 1С: идемпотентность по ключу, синхронизация справочников (GUID) |
| `src/connector/reports/` + `templates/reports/` | печатные формы (HTML/XLSX/JSON) |
| `src/connector/web/` | API панели (RBAC), `web/` — React-панель |
| `src/connector/license.py` | пакеты Старт/Бизнес/Холдинг, Ed25519 |
| `onec-extension/` | BSL-модуль и спецификация расширения 1С |

## Активные спецификации

- **`specs/depository-adapter.md`** — слой депозитарной сверки
  (DataSource/CustodySource, движок сверки, режимы `custody_mode`).
  Работать строго по фазам из раздела 9 спеки — по одной фазе за сессию,
  с тестами; не-цели из раздела 3 — жёсткая граница скоупа.
  Вопросы и противоречия фиксировать в `specs/questions.md`, не додумывать.

## Конвенции

- Русские докстринги с отсылками к пунктам ТЗ; идентификаторы — английские.
- Ошибки пользователю (detail в HTTPException) — по-русски, с действием.
- Новые внешние данные — всегда в два слоя: сырой payload + нормализованная модель.
- Каждая фаза/фича — атомарные коммиты с тестами; CI должен оставаться зелёным.
