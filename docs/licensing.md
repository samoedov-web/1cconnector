# Лицензирование

Годовая лицензия с файловой активацией (п. 10 ТЗ). Три пакета:

| | Старт | Бизнес | Холдинг |
|---|---|---|---|
| Юридические лица | 1 | 3 | без ограничений |
| Отслеживаемые кошельки | 3 | 10 | без ограничений |
| Обновления форм отчётности | — | ✓ | ✓ |
| Срок | 12 мес. | 12 мес. | 12 мес. |

Лимиты зашиты в подписанный файл лицензии — состав пакетов меняется
выпуском новых лицензий, без обновления кода. Индивидуальные условия —
флаги `--max-wallets` / `--max-organizations` при выпуске.

## Как это работает

- **Файл `license.json`** лежит рядом с коннектором (путь —
  `CONNECTOR_LICENSE_PATH`). Подписан Ed25519; открытый ключ вендора —
  в `CONNECTOR_LICENSE_PUBLIC_KEY`. Замена файла подхватывается без
  перезапуска.
- **Статусы:**
  - `valid` — всё работает;
  - `grace` — срок истёк, идёт льготный период (по умолчанию 14 дней):
    всё работает, панель предупреждает о необходимости продления;
  - `expired` — синхронизация с сетями и обмен с 1С остановлены;
    панель, отчёты и все накопленные данные доступны для чтения —
    данные клиента не запираются никогда;
  - `demo` — файла лицензии нет: полная функциональность с лимитом
    1 юрлицо / 1 кошелёк / без обновлений форм (режим пилота);
  - `invalid` — файл повреждён или подпись неверна: как expired,
    причина видна на мониторинге.
- **Enforcement:** создание юрлица/кошелька сверх лимита — 403 с
  указанием пакета; обмен с 1С при недействующей лицензии — 402 с
  человекочитаемой причиной (фоновое задание 1С пишет её в журнал
  регистрации и не падает); индексер прекращает опрос сетей.
- **Обновления форм отчётности** (пакеты Бизнес/Холдинг): право на
  получение новых шаблонов `templates/reports/` в течение срока лицензии
  (доставка — механизмом Продукта 3); флаг виден в статусе лицензии.

## Выпуск лицензий (вендор)

Закрытый ключ хранится только у вендора; `scripts/license_tool.py`
не входит в поставку клиенту.

```bash
# один раз: пара ключей
python scripts/license_tool.py keygen --out-dir keys/

# лицензия клиенту
python scripts/license_tool.py issue \
    --private-key keys/license_private.key \
    --tier business \
    --issued-to 'ООО «Вектор Трейд»' --inn 7701234567 \
    --months 12 --out license.json

# проверка
python scripts/license_tool.py inspect license.json --public-key <hex>
```

Клиенту передаются: `license.json` + значение открытого ключа
(один и тот же для всех клиентов, задаётся при внедрении в `.env`).

## Продление и апгрейд пакета

Выпустить новый `license.json` (тот же `issued_to`, новый срок или пакет)
и заменить файл на сервере клиента — перезапуск не нужен. При даунгрейде
лимиты применяются к новым объектам: существующие кошельки сверх лимита
продолжают синхронизироваться, но добавить новые нельзя.
