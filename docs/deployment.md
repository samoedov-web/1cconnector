# Развёртывание и безопасность (on-premise)

Дополнение к README для инженера, разворачивающего коннектор у клиента.
Покрывает п. 9–10 ТЗ: TLS, секреты, шифрование в покое, мониторинг, бэкапы.

## Схема

Один сервер клиента, Docker Compose: `db` (PostgreSQL 16), `api`
(FastAPI + веб-панель, применяет миграции при старте), `indexer`
(опрос сетей, стартует после health-check api). Наружу торчит только
порт api; publish порта БД запрещён.

## TLS

Коннектор слушает HTTP на 8000 — TLS терминируется reverse proxy на том же
сервере. Минимальный вариант с Caddy (автоматический сертификат Let's Encrypt
или внутренний CA клиента):

```
# Caddyfile
connector.company.local {
    reverse_proxy localhost:8000
}
```

или nginx:

```nginx
server {
    listen 443 ssl;
    server_name connector.company.local;
    ssl_certificate     /etc/ssl/connector.crt;
    ssl_certificate_key /etc/ssl/connector.key;
    location / { proxy_pass http://127.0.0.1:8000; }
}
```

В `docker-compose.yml` при этом привязать порт к loopback:
`ports: ["127.0.0.1:8000:8000"]`. Фоновое задание 1С ходит на https-адрес.

## Секреты

- Все секреты — только в `.env` (не в git; файл в `.gitignore`):
  `POSTGRES_PASSWORD`, `CONNECTOR_ONEC_EXCHANGE_TOKEN`,
  `CONNECTOR_SECRET_KEY`, `CONNECTOR_ADMIN_PASSWORD`, API-ключи провайдеров.
- Права на файл: `chmod 600 .env`, владелец — пользователь docker-деплоя.
- Генерация ключей: `openssl rand -hex 32` для SECRET_KEY и токена обмена.
- `CONNECTOR_ADMIN_PASSWORD` нужен только для первого старта (bootstrap
  учётки admin); после первого входа строку можно удалить из `.env`.
- При наличии у клиента Vault/секрет-хранилища — env-переменные
  подставляются оттуда, код изменений не требует.

## Шифрование в покое

Данные (обороты, адреса кошельков, контрагенты) чувствительны:

- диск/раздел с volume `pgdata` — LUKS (Linux) или средствами гипервизора;
- альтернатива на уровне СУБД — включить `pgcrypto`/TDE-совместимую сборку
  по политике клиента; коннектору это прозрачно.

## Неизменяемость первички

На PostgreSQL миграция `a90d41f2b7c1` вешает триггеры: доказательные поля
транзакций (хэш, суммы, адреса, сырой ответ ноды, момент получения),
снимки курсов и аудит-лог защищены от UPDATE/DELETE на уровне БД — даже
учётка с полным доступом к приложению не перепишет доказательную базу.
Обход возможен только суперпользователем СУБД — доступ к нему у клиента
должен быть отделён от эксплуатации приложения.

## Сетевые доступы (egress)

Индексеру и ядру нужны исходящие HTTPS к:

- источникам данных сетей: `api.trongrid.io` (или своя нода TRON),
  RPC-провайдер Ethereum (или своя нода);
- курсам: `www.cbr.ru` (ЦБ РФ), `api.coingecko.com` (нативные монеты,
  если не заменён биржевым источником из учётной политики);
- webhook алертов (если настроен).

Входящие: только 1С (фоновое задание) и браузеры пользователей панели —
через reverse proxy. Всё остальное закрыть.

## Мониторинг и алерты

- `GET /health` — проверка живости api (для внешнего мониторинга клиента).
- Экран «Мониторинг» в панели: статусы транзакций, возраст последнего скана
  по сетям, очередь разбора, документы обмена, последние алерты.
- `CONNECTOR_ALERT_WEBHOOK_URL` — POST JSON
  `{"severity","title","details","at"}` при событиях: все источники сети
  недоступны, расхождение источников (высоты или наборы транзакций), реорг.
  Приёмник — любой: свой обработчик, мост в Telegram/почту.

## Бэкапы

- БД: `docker compose exec db pg_dump -U connector connector | gzip >
  backup-$(date +%F).sql.gz` по cron; хранить вне сервера.
- `.env` — в защищённом хранилище (без него бэкап БД бесполезен для
  восстановления обмена: токены/ключ панели).
- Шаблоны отчётности `templates/` — в git клиента или в том же бэкапе.
- Восстановление: развернуть compose, восстановить дамп, положить `.env` —
  `alembic upgrade head` при старте догонит схему при необходимости.

## Обновления

```bash
git pull                # или доставка нового образа
docker compose build
docker compose up -d    # api применит миграции автоматически
```

Обновление шаблонов отчётности — заменой файлов в `templates/reports/`
без пересборки (том смонтирован read-only в контейнер).

## Перед коммерческим релизом

Пентест (п. 9 ТЗ) — внешний подрядчик; отчёт — аргумент продаж.
Чек-лист поверхности: панель (аутентификация, RBAC, IDOR), API обмена
(токен), reverse proxy (заголовки, TLS-конфигурация), контейнеры
(не root, актуальные базовые образы).
